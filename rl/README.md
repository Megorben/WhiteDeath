# Обучение с подкреплением для Mindustry

Цель: агент, который учится играть в Mindustry сам, через пробы и ошибки.
Сейчас реализован первый этап — **добыча ресурсов**.

## Как это устроено

```
┌───────────── Python ─────────────┐        stdin/stdout        ┌──────────── Java ────────────┐
│ pretrain.py (имитация, DAgger)   │  ── reset / step N ──▶     │ SimServer                    │
│ train.py    (MaskablePPO)        │                            │  настоящий движок Mindustry  │
│ policy.py   (свёрточная сеть)    │  ◀── карта, маска,         │  v146 без графики и без      │
│ mindustry_env.py (Gymnasium)     │      награда, ход эксперта │  ожидания реального времени  │
│ evaluate.py (сравнение агентов)  │                            │  + скриптовый эксперт        │
└──────────────────────────────────┘                            └──────────────────────────────┘
```

- **`sim/`** запускает настоящий движок Mindustry из `server.jar`, но останавливает игровой цикл — так же, как это делают тесты самой игры. Время идёт только по команде агента, поэтому один процесс выдаёт примерно 1300 шагов в секунду (≈80 000 игровых тиков, в ~1300 раз быстрее реального времени).
- **`python/`** — окружение Gymnasium, нейросеть и обучение (stable-baselines3 + sb3-contrib).

## Задача «добыча»

- Каждый эпизод генерируется новая карта 24×24: стены, пятна медной и свинцовой руды, ядро в случайном месте.
- За шаг агент может поставить механический бур (2×2), конвейер (одно из четырёх направлений) или ничего не делать. Постройка появляется сразу и стоит ресурсов ядра: бур — 12 меди, конвейер — 1. После действия проходит 1 секунда игрового времени.
- Эпизод длится 150 шагов. Награда — медь и свинец, доставленные в ядро (×0.1).
- **Shaping награды** (`--shaping 1`, включён по умолчанию). Без подсказок агент почти никогда не получает награду: нужно одновременно поставить бур на руду и проложить правильную цепочку конвейеров. За 30 тыс. шагов обучения без shaping он оставался на уровне случайного. Поэтому есть «потенциал» базы: каждый бур весит тем больше, чем ближе его цепочка конвейеров подходит к ядру, а подключённый бур весит вдвое больше любого неподключённого. Агент получает γ·P' − P. Такой shaping на основе потенциала (Ng et al., 1999) доказанно не меняет оптимальную стратегию, а только ускоряет её поиск.
- **Маска действий:** агент выбирает только среди допустимых действий — клетка свободна, бур стоит на руде, ресурсов хватает. Из 2881 возможного действия обычно допустимы 1500–1800.

### Нейросеть

Политика полностью свёрточная: она выдаёт логит для каждой клетки и каждого типа постройки — «бур здесь», «конвейер здесь, вверх» и так далее. Глобальные рассуждения идут на половинном разрешении (как в U-Net): там расширенные (dilated) остаточные свёртки дают каждой клетке обзор всей карты, поэтому сеть может «знать», где ядро.

Политика **иерархическая**: p(действие) = p(тип) · p(клетка | тип), где тип — ждать, бур или конвейер, а вероятности клеток нормируются только по допустимым. Без этого ~1750 из ~1800 допустимых действий — конвейеры: необученный агент тратит всю медь на случайные конвейеры раньше, чем успевает поставить хоть один бур.

### Скриптовый эксперт

Бот на правилах встроен прямо в симулятор (`SimServer.expertAction`) и решает только по текущему состоянию карты:
1. Если какой-то бур ещё не подключён, он ставит следующий конвейер для того бура, которому ближе всего до ядра. Путь ищется поиском в ширину, причём можно влиться в уже подключённую цепочку.
2. Иначе он ставит бур на самую богатую руду, которую дёшево подключить.
3. Иначе ждёт.

Он нужен для трёх вещей: как планка, которую ИИ должен превзойти; как учитель для имитации; и как «подсказчик» в DAgger — он может сказать правильный ход в **любом** состоянии, включая те, куда завёл ученик своими ошибками.

### Наблюдение

15 плоскостей 24×24: руда меди и свинца, стены, ядро, буры, конвейеры по 4 направлениям, «в постройке есть предметы», запас меди, запас свинца, прогресс эпизода и две маски допустимости — «здесь можно поставить бур» и «здесь можно поставить конвейер».

## Запуск

Нужны Java 17+ и Python 3.10+.

```sh
# 1. Собрать симулятор (сам скачает server.jar Mindustry v146)
rl/sim/build.sh

# 2. Установить зависимости
cd rl/python
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

# Готовую модель можно сразу сравнить с ботом на новых картах:
python evaluate.py --model ../models/mining.zip --episodes 20 --render

# 3. Имитация эксперта (DAgger), ~1 час на 4 ядрах CPU
python pretrain.py --out runs/dagger.zip

# 4. Дообучение с подкреплением + продолжение имитации (прогресс каждые 10 000 шагов)
python train.py --init runs/dagger.zip --timesteps 2000000 --envs 4
tensorboard --logdir runs        # графики, по желанию

# 5. Сравнение со случайным агентом и скриптовым ботом на новых картах
python evaluate.py --model runs/mining/final.zip --episodes 20 --render
```

## Результаты

Доставлено ресурсов за эпизод на 20 картах, которых не было в обучении (`evaluate.py`, сиды 10000–10019):

| Агент | Ресурсов за эпизод |
|---|---|
| Случайные допустимые действия | 0.7 |
| PPO с нуля, ~50 тыс. шагов | ~8 ¹ |
| Behavior cloning (старый бот, 300 эпизодов) | 22.0 ± 38.0 |
| DAgger (`models/dagger.zip`) | 201.7 ± 81.2 |
| DAgger → PPO (KL-limited, без имитации) | падение ~230 → ~175 ² |
| **DAgger → PPO + имитация эксперта, 300 тыс. шагов** (`models/mining.zip`) | **237.5 ± 79.6** |
| Скриптовый эксперт | 319.9 ± 91.2 |

¹ Замерено во время обучения. В тех запусках была ошибка в подсчёте shaping, поэтому цифра занижена; честного перезапуска PPO с нуля после исправления пока не было.

² Замерено во время обучения (стохастическая политика), запуск остановлен на 80 тыс. шагов.

Чекпоинты последнего запуска при детерминированной оценке: 100 тыс. шагов — 228.8, 200 тыс. — 232.1, 300 тыс. — 237.5.

Что из этого следует:
- **RL с нуля** на такой задаче буксует: награда слишком редкая, а действий слишком много.
- **Простое повторение за ботом** (behavior cloning) ломается из-за накопления ошибок: одна неправильно повёрнутая лента — и цепочка до ядра не достроена, а такие состояния бот никогда не показывал.
- **DAgger** решает это: ученик играет сам, а эксперт показывает правильный ход в каждом состоянии, куда тот попал. Результат вырос в 9 раз — до 63 % уровня эксперта на незнакомых картах.
- **Чистый PPO поверх DAgger** постепенно «забывает» выученное: даже с ограничением KL шумный градиент в пространстве из 2881 действия размывает политику быстрее, чем находит улучшения.
- **PPO + продолжение имитации** (как DAPG и kickstarting из литературы): после каждого обновления PPO сеть ещё раз учится повторять ход эксперта в состояниях, где только что побывала. Так агент держит уровень и медленно растёт: 237.5, то есть 74 % уровня эксперта и +18 % к DAgger.

Агент пока **не превзошёл** скриптового эксперта. Все эксперименты шли на 4 ядрах CPU со скоростью ~80 шагов/с. На видеокарте те же 300 тыс. шагов заняли бы минуты, а не час, и можно было бы обучать на порядки дольше. Чтобы обогнать эксперта, а не только догонять его, следующий шаг — постепенно снижать вес имитации (`--imitation-coef`) по мере обучения.

## Дорожная карта

1. ✅ **Добыча:** буры и конвейеры, доставка в ядро.
2. **Производство:** графитовый пресс, кремниевый завод, энергия. Награда за ценные ресурсы.
3. **Оборона:** волны врагов. Агент строит турели и подводит к ним боеприпасы, награда — пережитые волны.
4. **Строительство через юнита:** реальное время постройки вместо мгновенного.
5. **Настоящие карты:** Ground Zero, Frozen Forest и другие вместо сгенерированных.
6. **Мод-клиент:** обученная модель играет в настоящей игре (экспорт в ONNX + Java-мод).
