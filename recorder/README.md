# WhiteDeath Recorder

Клиентский мод для Mindustry (ПК, build 160+, как в Steam). Записывает PvP-матчи, которые вы смотрите или играете, чтобы потом учить на них ИИ.

- **Пассивный.** Мод ничего не отправляет на сервер: он только сохраняет то, что ваш клиент и так получает во время игры или наблюдения.
- **Чисто клиентский** (`hidden: true`). Сервер не требует этот мод у игроков, поэтому можно заходить на любые серверы.
- **Анонимный.** Вместо ников сохраняются хэши с солью, уникальной для вашей установки. Один и тот же игрок получает один и тот же псевдоним во всех матчах, поэтому потом можно посчитать рейтинги, но восстановить ник по записи нельзя.

> Владельцы серверов вправе запрещать запись матчей. Когда накопится хорошая коллекция записей, стоит написать админам сервера. Многие охотно помогают таким проектам, а запись прямо с сервера даст более полные данные.

## Установка

1. Скачайте `dist/WhiteDeathRecorder.jar`.
2. Положите его в папку модов:
   - Windows: `%AppData%\Mindustry\mods\`
   - Linux: `~/.local/share/Mindustry/mods/`
   - macOS: `~/Library/Application Support/Mindustry/mods/`
3. Перезапустите игру. В **Настройках** появится раздел «Запись матчей (WhiteDeath)».

Если сервер не пускает с ошибкой **Incompatible mods / Unnecessary mods**, значит у вас включён мод, которого нет на сервере. Например, контентный мод White Death с турелью: выключите его в меню «Моды». Сам регистратор сервер не видит и не мешает подключению.

Android не поддерживается: Java-моды там нужно собирать отдельно, в формате dex.

## Как пользоваться

Просто заходите на PvP-сервер и играйте или наблюдайте за матчами. Пока идёт запись, в правом нижнем углу горит **● REC** с таймером.

Запись начинается при загрузке карты и заканчивается, когда матч завершён, загружается следующая карта или вы выходите с сервера.

Записи сохраняются в папку `whitedeath-recordings` рядом с папкой `mods`. Один матч занимает одну папку:

| Файл | Что внутри |
|---|---|
| `events.jsonl.gz` | журнал событий: одна строка JSON на событие |
| `keyframe-<тик>.msav` | полный снимок мира в стандартном формате сохранений Mindustry. Пишется в начале матча и раз в минуту (интервал настраивается) |

Сводка по записям (из папки `rl/python` репозитория):

```sh
python recordings.py "%AppData%/Mindustry/whitedeath-recordings"         # все матчи
python recordings.py "%AppData%/Mindustry/whitedeath-recordings" --1v1   # только 1v1
```

## Формат `events.jsonl.gz`

Каждая строка — объект с полем `t` (игровые тики от начала матча, 60 в секунду) и `e` (тип события).

| `e` | Как часто | Содержимое |
|---|---|---|
| `start` | 1 раз | `format` (сейчас 2), версия игры, карта, размер, правила, команды и их ядра; таблицы названий `blocks`, `units`, `items`, `commands`, `stances` (id → имя); рельеф `terrain` (пол, руда, стены как массивы uint16 в base64) |
| `blocks` | каждые 0.5 с, если что-то изменилось | `c`: список `[x, y, блок, команда, поворот, стройплощадка]`; блок `-1` значит, что постройка исчезла. Первый снимок содержит всю базу |
| `units` | каждые 0.5 с | `u`: `[id, тип, команда, x·10, y·10, здоровье %, команда RTS, цель x·10, цель y·10, псевдоним игрока или null, [стойки]]`, координаты в клетках; стойки — id из таблицы `stances` (стоп, не стрелять, преследовать, патруль…) |
| `players` | каждые 5 с | псевдоним, команда, позиция, юнит; `me: true` — это вы |
| `cores` | каждые 5 с | ресурсы в ядрах каждой команды, насколько их видит клиент |
| `built` | по событию | постройка завершена или разобрана: где, что, команда, кто строил |
| `destroyed` | по событию | постройка уничтожена |
| `config` | по событию | постройка перенастроена: сортировщик, завод юнитов и т. п. |
| `keyframe` | по событию | записан снимок мира |
| `end` | 1 раз | причина (`game-over`, `next-map`, `left`) и победитель |

## Что проверено и что нет

Проверено автоматически (`./build.sh --test`) на движке Mindustry build 160.7 без графики:
- запись начинается на PvP-карте и заканчивается при победе;
- постройки, юниты, команды, разрушения и победитель записываются;
- id блоков совпадают с таблицей названий;
- ключевые кадры загружаются обратно со всеми ядрами и постройками;
- загрузчик модов build 160.7 признаёт мод поддерживаемым. Java-моды с `minGameVersion` ниже 154 он помечает устаревшими и не запускает; именно поэтому первая версия, собранная под v146, не запустилась.

**Не проверено**, потому что нужен настоящий клиент на настоящем сервере:
- меню настроек и индикатор REC;
- какие данные сервер присылает зрителю. Например, ресурсы вражеского ядра и RTS-цели чужих юнитов сервер может не синхронизировать: тогда эти поля будут пустыми или неполными.

Первым делом запишите один короткий матч и пришлите вывод `recordings.py` для этой папки: по нему будет видно, что реально приходит с сервера.

## Сборка

```sh
recorder/build.sh          # dist/WhiteDeathRecorder.jar
recorder/build.sh --test   # плюс автоматическая проверка
```
Нужен JDK 17+.
